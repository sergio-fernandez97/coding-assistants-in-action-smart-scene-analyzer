# Prompt — DevOps Agent

**When:** Lesson 01, step 10. After the README and architecture exist.

---

```
Set up the build, containerization, and CI for the Smart Scene Analyzer.

Read first: CLAUDE.md, pyproject.toml, docs/architecture.md, .env.example.

Produce:

app/app.json
- Expo config: name, icon, and the permissions the app actually needs.
- The native config plugins both on-device ML runtimes require. Name them explicitly;
  a missing plugin fails at native build time with an error that names nothing useful.

app/metro.config.js
- resolver.assetExts must include 'tflite' and 'pte'. Without this the bundler
  silently omits the model files and the app fails at load, pointing at a path
  that looks correct.

.gitignore
- Must exclude: data/, datasets/, mlruns/, runs/, .venv/, .git/, notebooks/,
  *.pt, *.onnx, *.tflite, *.pte, node_modules/, app/ios/, app/android/
- The last two are generated by `expo prebuild`. Committing them means the next
  prebuild silently discards whatever anyone hand-edited in them.

.github/workflows/ci.yml
- Trigger on push and pull request.
- Jobs ordered cheapest-first: ruff check → ruff format --check → mypy → pytest.
  A formatting error should fail in seconds, not after a full test run.
- Cache the uv environment.
- Run `pytest -m "not integration"`. CI has no model weights and no exported
  artifacts, and a job that silently skips is worse than one that never ran.
- Do NOT add a build, publish, or deploy job. There is no image and no registry.

Then verify your own work, and report the actual output rather than asserting it:
  python3 -c "import json; json.load(open('app/app.json'))"
  grep -E "tflite|pte" app/metro.config.js
  git check-ignore -v app/ios app/android node_modules
If any of the three does not do what you claimed, fix it and run it again.

Constraints:
- Never put a secret in an EXPO_PUBLIC_ variable — that prefix embeds the value in
  the app bundle, readable by anyone who installs it. This app has nothing to
  authenticate to, so it should carry no credentials at all. Development-time
  secrets come from the environment and, in CI, from GitHub Actions secrets.
- Do NOT add a deployment target of any kind. Under the on-device architecture
  "release" is an app-store submission, and that is a project decision I have not
  made.
- MLflow hosting is still undecided. Default to a local tracking server started with
  `uv run mlflow server`, and add a comment saying it is a placeholder pending that
  decision.
```

---

## Verification

```bash
python3 -c "import json; json.load(open('app/app.json')); print('app.json: valid')"
grep -E "tflite|pte" app/metro.config.js
git check-ignore -v app/ios app/android node_modules data/dummy runs/dummy
```

`git check-ignore` printing nothing for a path means that path is **not** ignored — it
is the one of the three that fails silently in the direction that costs you something.

Then confirm no secret is heading for the bundle:

```bash
grep -rn "EXPO_PUBLIC" app/ 2>/dev/null && echo "REVIEW EACH" || echo "clean"
git status --porcelain | grep -E '\.env$' && echo "LEAK — fix .gitignore" || echo "clean"
```

Anything with the `EXPO_PUBLIC_` prefix is embedded in the app bundle and readable by
anyone who installs it. A build flag there is fine; a credential is not, and this app has
nothing to authenticate to.

## Reject and re-run if

- The agent reports a successful build it did not actually run
- Any `EXPO_PUBLIC_` variable holds a credential rather than a build flag
- The runtime stage contains `torch` or `ultralytics`
- CI runs tests before lint
- A cloud provider appears anywhere
